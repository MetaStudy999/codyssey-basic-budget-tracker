# B2-1 — 사전 역량 진단 및 동등 사후 평가 설계 V1.0

> 실제 학습자에게 문제를 실시하지 않았음. 본 문서는 평가 도구 설계 상태이다. QG-02의 실제 성취 비교는 NOT_VERIFIED.

## 진단 사용 원칙
실행 전 종이 예측(허용), 실제 수행은 04 승인 이후. 정답·힌트는 사전 독립 응답이 끝난 뒤에만 제시한다. 개인 식별정보/비밀정보 수집 금지. 사후 문제는 같은 능력·유사 난이도·다른 값으로 구성한다.

| ID/LO | 사전 문제(설명·예측) | 사후 동등 문제 | 평가 준거 |
|---|---|---|---|
| PRE-01/LO-01 | 지출 3000, 2000이 리스트에 있을 때 합계 예측 | 지출 4000, 1500의 합계 예측 | 순회와 덧셈 구별 |
| PRE-02/LO-02 | 3종 데이터파일이 필요한 이유와 재실행 시 차이 설명 | 거래/분류/예산 파일 재열기 시나리오 설명 | 메모리 vs 영구 저장 구별 |
| PRE-03/LO-03 | add 뒤 list, update, summary 순서 그림 | category 뒤 add, search, budget 흐름 그림 | 입력→검증→저장→조회 |
| PRE-04/LO-04 | yield를 쓰는 함수가 파일을 언제 읽는지 예측 | 다른 항목 수로 iterator 소모 시점 예측 | 전체 적재와 순차 로드 비교 |
| PRE-05/LO-05 | CLI/Service/Repository 책임을 선택하고 근거 제시 | 새 예산 조회에 필요한 계층 구별 | 결합도·책임 분리 이해 |
| PRE-06/LO-06 | 날짜 2026-13-40 입력 시 결과 설계 | 금액 -10 입력 시 결과 설계 | 이유·힌트·종료코드 |
| PRE-07/LO-07 | CSV 정상 2행·불량 1행 시 정책·건수·종료코드 예상 | CSV 정상 3행·불량 1행 시 동일 정책·건수·종료코드 예상 | 같은 역량: 부분 성공·안전·사용자 안내 |
| PRE-08/LO-07 | JSONL vs CSV의 장단점과 10만 건 병목 설명 | 동일 조건의 JSONL/CSV 비교·개선 대안 설명(다른 사례) | 같은 역량: 저장 방식·확장성 |

## 독립 평가·점수 기록 양식
각 문항 0=미응답/오류, 1=일부 설명, 2=근거·흐름이 명확함(내부 교육 루브릭·공식 평가 점수 아님). 사전·사후 각각 16점 만점. AI 힌트 H1~H4와 도움 여부를 함께 기록한다.

## 잘못 이해하기 쉬운 점·처방
- 리스트가 자동 입력 검증을 하지 않음 → 검증 함수 필요.
- JSONL 파일을 3개로 나누어도 원자적 다중 파일 트랜잭션을 자동 보장하지 않음 → 정책/한계 설명.
- yield는 지연 실행/반복 소비를 의미, 무조건 최신순 출력을 보장하지 않음 → 역방향 읽기 전략 필요.
- README나 사전 테스트 계획이 있다고 학습자가 독립 L4 구현을 한 것으로 간주하지 않음.

사전/사후 문제 설계(DOC)와 실제 학습 성취(LEARNER)를 분리하여 기록. 지금은 실제 응답 점수·재검증 결과 없음.

## 문제 동등성 검토 기준
PRE-01~08의 사전·사후는 동일 LO와 동일 0~2점 평가척도를 사용한다. 사례 값은 바꾸되 **비교하는 개념과 필요한 추론 단계를 유지**한다. 실제 사전/사후 응답은 아직 없어 향상률이나 L1~L5 PASS를 기록할 수 없다.
