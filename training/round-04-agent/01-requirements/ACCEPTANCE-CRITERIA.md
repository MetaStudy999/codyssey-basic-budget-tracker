# B2-1 수용 기준 및 공식/선택 범위

> 01 단계 설계용 수용 기준. 이 표는 실행 결과가 아니라 앞으로 테스트할 조건이며, 공식 PDF 범위를 넘어서는 수치 기준은 "설계 제안"으로 표기한다.

## 수용 판단
- 정상 흐름: add → list → search → update → delete, category 관리, summary, budget, CSV import/export를 CLI로 시연하고 종료 코드 0.
- 데이터 내구성: 프로그램 종료→재실행 후 거래·카테고리·예산 3종이 여전히 존재. 3종 저장 파일 실제 점검.
- 검증: 날짜 오류/0·음수 금액/알 수 없는 type·category/없는 거래/깨진 CSV/권한 문제에서 사유와 힌트가 보이고 비정상 종료 코드는 0이 아님(상황별 오류 정책을 03-5에서 상세화).
- 구조: 클래스 2개 이상, 코드 모듈 3개 이상, 타입 힌트, yield 제너레이터(list/search), 사용된 데코레이터 1개 이상; 함수와 역할 설명 가능.
- 성능: 공식 임의 속도 수치 없음. 거래 10만 건은 기존 평가표의 설계·병목 설명 질문이며 미션 필수 성능 지표 아님.
- 문서: 환경 Python 3.10+, 외부 패키지 금지, README 설치·실행·경로·포맷·명령·CSV 스키마.
- 보안·독립성: 실제 비밀 값 없이 샘플; 기존 archive 참조는 현재 PASS의 증거가 아니다.

## 공식 평가와 연결
| 기존 평가 ID(내부명) | 기준 | 이 단계 이후의 증빙 |
|---|---|---|
| E1 | 기능과 예외 처리 | T-CMD/ADD/LIST/SEARCH/UPDATE/DELETE/BUDGET/CSV/ERROR 실행 |
| E2 | 모듈·클래스 설계 | 구조도, 실제 클래스·함수·파일·SHA |
| E3 | 제너레이터·데코레이터·타입 힌트 | 코드 추적/실제 제너레이터·데코레이터 테스트 |
| E4 | 저장 포맷 및 확장성 | JSONL/CSV 비교, 10만 건 병목·불량 CSV 처리 설명 |

**최종 판정:** 요구사항 전체 실제 기능 PASS + 재실행·실패경로 테스트 PASS + Evidence + 독립 평가 설명 + Secret 0을 모두 확인한 경우에만 CLEAR를 검토한다.

## 수치·경계 예시 — 실행 전 EXPECTED
| 기준 | 입력 | 기대 결과 |
|---|---|---|
| REQ-09/13 최신순 | 먼저 2026-10-30, 나중에 2026-10-01 등록 | 날짜 표시 10-30 → 10-01 |
| REQ-14 요약 | 같은 월 수입 100000, 지출 30000 | 잔액 70000 |
| REQ-15 예산 | 예산 20000, 지출 30000 | 사용률 150%, 초과 경고 |
| REQ-04/20 잘못된 날짜 | 2026-02-30 | 원인+힌트, 최종 오류 종료 비0(재입력 흐름은 별도 검증) |
| REQ-17 CSV 부분 오류 | 정상 2행+불량 날짜 1행 | imported=2, skipped=1, 행별 오류, exit=2(내부 설계) |
