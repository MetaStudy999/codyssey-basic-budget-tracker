## 학습 진행
선행 지식(변수·함수·리스트·딕셔너리·입출력)을 한 문장으로 설명 → 작은 예로 예측 → 승인된 환경에서 실행 → 조사·수정 → 코드 보지 않고 독립 구현 → 한계/대안 설명.

- H1~H4: 질문→개념→절차→예제 해설의 순서로 필요한 만큼만 도움.
- L1~L5: 코드 보며 설명 → 구조도만 보고 설명 → 무자료 설명 → 빈 환경 재현 → 새로운 조건 응용.
- M01~M16 전체를 모든 활동에 강제하지 않는다. 해당 목표의 진단·오답에 따라 적합 활동을 선택.
- QG-01: LO ↔ REQ ↔ 테스트 ↔ 증빙을 유지; QG-02: 동등 사전/사후 진단; QG-03~08은 이후 실제 교육·시험에서 검증.

**상태:** 학습 설계 문서; 학습자 실제 사전 평가·런타임·L1~L5 모두 NOT_VERIFIED.

## 보완된 독립 설명 질문
- LO-02: 데이터 파일 3개를 나누었다고 다중 파일 원자성이 보장되는가? **아니요**. 각 파일의 저장·오류 처리 정책은 별도다.
- LO-03/04: 거래 입력순과 날짜순이 다른데도 최신순 제너레이터를 유지하려면? **거래 파일의 날짜 정렬 불변식을 유지하고 순차적으로 yield**하도록 설계한다.
- LO-06: CSV 3행 중 1행이 잘못되었을 때 이번 설계에서 오류 종료 2를 선택한 이유는? 부분 저장을 성공으로 오해하지 않도록 함.
- LO-07: 정렬된 JSONL 방식에서 데이터 10만 건의 병목은? 새 거래 추가나 날짜 수정 시 파일 전체 재작성 가능성이 커짐. 이는 공식 성능 수치 기준이 아니라 평가 설명 문제이다.
