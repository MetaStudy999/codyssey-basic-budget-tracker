# B2-1 03-4 — 이벤트·데이터·상태 흐름 설계 V1.0

> 설계도는 실행 결과가 아니며 JSONL 파일로 구현 전 예상 경로를 나타낸다.

## 핵심 이벤트 흐름
~~~mermaid
flowchart TD
 A["add/update/delete/search"] --> B["CLI 입력·옵션"]
 B --> C["Service: 날짜·금액·분류 검증"]
 C --> D{"정상?"}
 D -->|실패| X["오류+힌트/비0 종료"]
 D -->|통과| E{"작업 종류"}
 E -->|추가| F["ID 생성·거래 추가"]
 E -->|수정·삭제| G["대상 ID 찾기·안전한 재작성"]
 E -->|조회| H["yield로 파일 순차 읽기·필터"]
 F --> I["JSONL 파일"]

 I --> K["요약·예산 계산"]

~~~

## 상태 불변식
- id: 거래를 식별하고 기존 ID와 충돌하지 않음.
- date: YYYY-MM-DD 실제 유효 날짜.
- amount: 양수 정수, type: income 또는 expense.
- category: 등록된 이름; 실제 거래에서 사용하는 분류를 무조건 제거하지 않음.
- 거래 삭제 후 존재하지 않는 ID를 다시 수정·삭제하면 실패 안내.
- 예산과 거래는 재실행 후 재조회 가능.
- summary: 총수입 - 총지출 = 잔액. 지출만 월 예산 사용률에 반영(설계 선택).
- 검색 조건은 동시에 주어질 때 AND(교집합)로 적용하는 안을 채택하며 공식 PDF의 수치·논리를 확장하지 않는다.
- 최신순: 날짜 역순을 1차 기준, 동일 날짜의 처리 순서는 명시적 안정 규칙을 04 구현 전에 확정(제안: 생성 ID 역순). 파일 끝에서부터 읽는 방식은 UTF-8 다바이트 경계/개행 처리에 유의.

## 상태 변화 예시(종이 실습)
교육용/NOT_EXECUTED: 2026-10-01 수입 100000, 지출 30000 → 잔액 예상 70000. 예산 20000 설정 시 지출 예산 초과 경고 예상. 직접 숫자를 바꾸어 결과를 설명한다.

## V0.1 검토→V1.0
V0.1: add→저장→조회 흐름만 작성. P10 최신순과 yield 동시 달성 어려움 → 역방향 파일 읽기 전략의 검증 필요 기록. P11 안전한 update/delete 누락 → 임시 파일 후 원자적 교체. P12 category 사용중 삭제/예산 경고 누락 → 데이터 불변식 추가. V1.0: 주요 이벤트·예외까지 연결.
