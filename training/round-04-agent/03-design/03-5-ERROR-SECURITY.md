# B2-1 03-5 — 오류·파일 경로·CSV 부분 성공 정책 V1.1

> 설계 문서 / 실제 명령 미실행. 공식 PDF 4~8쪽: 입력 검증, CSV 스키마, traceback 대신 원인+힌트, 오류 종료 비0.

## 입력 조건/오류 힌트
| 입력 | 검증 | 실패 시 안내 |
|---|---|---|
| date | 실제 존재하는 YYYY-MM-DD | 예: 2026-10-30 형태 입력 |
| type | income / expense | 허용 유형 제시 |
| amount | 양수 정수(0/음수 금지) | 금액은 1 이상 |
| category | 등록된 분류 | category list/add 안내 |
| id | 활성 거래 존재 | list에서 ID 확인 |
| --month | 유효한 YYYY-MM | 월 형식 안내 |
| --limit/--top | 1 이상 정수 | 범위와 도움말 안내 |
| --from/--to | 시작일≤종료일 | 기간 순서 수정 안내 |
| 파일·CSV | UTF-8, 정확한 6개 헤더, 행별 규칙 | 행 번호·원인·해결 방법 |

## 내부 저장 경로와 CSV 입력/출력 구분
- `--data-dir`: transactions/categories/budgets JSONL을 **저장하는 내부 데이터 폴더**. 기본 `./data`.
- `import --from <CSV>`: 지정된 CSV를 **읽음**, 기존 파일을 임의 삭제하지 않음.
- `export --out <CSV>`: 사용자가 명시한 외부 CSV 경로에 쓰기 허용. 데이터 폴더 내부로 한정하지 않음. 대상 경로가 내부 JSONL 파일과 동일하거나 예상 밖 덮어쓰기를 유발하면 오류 처리(안전 정책 제안). **확정한 설계 선택:** 기존 CSV가 존재하면 기본적으로 내보내기를 거부하고, 사용자가 명시적으로 `--overwrite`를 준 경우에만 교체(이 추가 옵션은 공식 필수 아님).
- OS 파일 권한·디스크 공간·중단 상황을 각 테스트로 검증. 경로 처리 시 개발 머신의 다른 파일을 지우지 않는다.

## CSV 고정 스키마(공식)
`date,type,category,amount,memo,tags`, UTF-8, 헤더 포함. tags는 쉼표 구분 문자열이므로 필드 자체에 쉼표가 들어가면 CSV 따옴표 이스케이프가 필요하다. 파이썬 표준 `csv` 모듈 사용을 권장.

## 부분 성공 정책(공식의 구현 선택안)
1. 전체 파일의 헤더/인코딩이 잘못된 경우: **어떤 거래도 저장하지 않음**. 오류+힌트, exit=2(설계값).
2. 헤더는 정상, 여러 행 중 불량 행이 섞인 경우: 유효 행만 저장하고 `imported=N, skipped=M`, 불량 행 번호와 사유를 출력. **부분 성공이므로 exit=2**로 사용자에게 완전 성공 아님을 알린다(내부 설계 선택; 공식은 특정 오류코드를 지정하지 않음).
3. 모든 행 정상: 전부 저장, exit=0. **재시도 정책:** 동일 파일을 다시 가져오면 별도의 새 거래로 추가될 수 있음을 명확히 경고한다. 이번 최소 구현에서는 파일 지문 기반 중복 제거를 강제하지 않는다(공식 필수 요구 아님). '금액·날짜가 같음'만으로 진짜 중복이라고 단정하지 않는다.
4. 유효 행을 저장하는 과정에서 I/O 실패 시 조용히 성공 처리하지 않고 원인/힌트와 비0 종료, 저장된 범위를 보고한다. 파일 일부만 반영되는 한계는 평가 E4에서 설명한다.

**주의:** 프로그램 정상 종료는 0, 오류 종료는 0이 아닌 값으로 처리한다는 공식 요구를 지키기 위해 부분 오류도 비0을 채택했다. 이 정책은 공식의 세부 종료코드 강제가 아닌 설계 판단이다.

## 파일 교체·보안
- update/delete에서 대상 미존재 시 원본 그대로 + 비0 종료. 임시 파일은 동일 디렉터리에 만들고 가능하면 fsync 후 os.replace, 실패 시 임시파일 제거.
- 원본 손상과 임시파일 잔존, 디스크 용량 부족, 권한 거부, 잘못된 JSONL에 대한 회복 안내.
- 가상 거래 데이터로만 증빙. 개인 거래·계좌·비밀키를 README/로그/GitHub에 넣지 않음.
- 웹, 인증, 외부 AI API는 공식 필수 아님.
