# B2-1 03-5 — 입력·출력·오류·보안 설계 V1.0

> 명령줄 프로그램의 실패 처리를 기획하는 문서. 실제 오류 재현·스크린샷은 아직 없다.

## 입력 검증
| 입력/상황 | 올바른 조건 | 잘못되었을 때의 예상 처리 |
|---|---|---|
| date | 실제 존재하는 YYYY-MM-DD | 날짜 형식+예제 힌트 |
| type | income/expense | 가능한 값 안내 |
| amount | 양수 정수 | 0·음수·문자열 거부 |
| category | 현재 등록된 분류 | category list/add 안내 |
| id | 존재하는 거래 id | 대상 없음, 비0 종료 |
| month | YYYY-MM, 유효 월 | 예: 2026-10 안내 |
| --limit / --top | 안전한 양의 정수 | 범위 설명·오류 종료 |
| CSV | UTF-8+정확한 헤더/스키마 | 파일·행별 원인, 정책에 따라 건너뛰기 |
| data-dir | 접근 가능한 작업 경로 | 접근/쓰기 권한 안내, 정상 데이터 보호 |

## CSV 정책 선택안
고정 스키마: date,type,category,amount,memo,tags, 헤더와 UTF-8 필수. 불량 행이 섞인 import는 유효한 행만 반영하고 imported/skipped/행 번호·원인 보고하는 **부분 성공** 안을 채택한다. 원자적 전체 롤백이 요구된 것은 아니므로 기존 평가 E4에서 선택 이유와 한계(부분 저장, 재시도 중복 가능성)를 설명한다. 구현 전 ID 중복 방지와 오류 종료 조건을 명확히 한다.

## 저장 및 오류 경계
- 절대 경로·상대 경로를 무턱대고 변경하지 않는다. 기본 ./data 및 --data-dir의 사용 범위를 명시하며, 프로그램은 사용자가 지정한 경로 밖을 쓰지 않도록 제한한다(설계 선택).
- 수정/삭제 중 파일 실패 시 원본 손실을 방지할 임시 파일 + 안전한 교체를 고려. 남은 임시 파일·권한 거부·디스크 부족·깨진 JSONL의 오류 시나리오 테스트 필요.
- 파일에 개인 정보, 계좌번호, 실수 비밀번호를 시험 데이터로 사용하지 않는다. 비밀키가 없어도 GitHub 증빙·로그에 실제 개인 지출 내역이 노출되지 않게 가상 거래 데이터를 쓴다.
- 사용자에게 traceback을 원문 출력하지 않고, 원인+대응 힌트를 표시. 성공 exit=0, 오류 exit≠0.
- 보안 범위: 이번 공식 과제에 인증·웹서버·외부 API는 없으며, 이를 새 필수 구현으로 추가하지 않는다.
